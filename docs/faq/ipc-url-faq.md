> 提交软件、回声洞投稿与反馈中心的常见问题

## 提交软件必须填哪些项

必填项：`id`、`name`、`category`、`tagline`、`description`、`system`、联系方式，以及**至少一条文件直链**。提交页会在前端进行拦截校验。

`id` 仅允许英文小写、数字与短横线，不得包含 `?` `&` `=` 等符号——历史数据中有 5 个畸形 `id` 曾导致详情页显示「未找到该软件」，现已修正。

## 「从 GitHub 一键读取」是什么

提交页提供的辅助功能：填入 GitHub 仓库地址后，自动读取该仓库的 Releases 与资产信息，填充版本号、体积与下载直链。未登录的 GitHub 接口限流 60 次/小时/IP，一次读取约消耗 2 次。

## 校验值怎么填

只填十六进制那一串即可，算法按长度自动识别：

| 长度 | 算法 |
| --- | --- |
| 32 | MD5 |
| 40 | SHA-1 |
| 56 | SHA-224 |
| 64 | SHA-256 |
| 96 | SHA-384 |
| 128 | SHA-512 |

带 `MD5:` 前缀或按字节分隔（冒号 / 空格）的写法均可直接粘贴，提交时会自动规范化。

::: warning 不要把校验值写进 note
128 位哈希没有可断行的地方，整串写入 `note` 会导致文字溢出卡片。
:::

## 为什么我的联系方式是密文

「提交软件」与「反馈中心」的联系方式在浏览器本地用 age 公钥加密后再提交。公开的提交记录与复制出的文本中均为密文，仅维护者可用私钥解密查看。这是有意设计——该字段会被原文发布在公开 Issue 中，明文一旦泄露无法撤回。

## 提交后多久会处理

提交进入仓库的 `submissions/` 目录，由工作流自动创建 `[待审核]` Issue。维护者在 Issue 上打标签后合并或驳回。具体时效取决于维护者排期。

## 为什么提交成功但没有发布

可能原因：草稿已创建但尚未被审核。请通过提交页给出的入口或 QQ 群查询进度。若多次提交同一软件，最早的草稿可能因幂等键基于文件路径而各自独立等待审核。

## 反馈提交失败怎么办

1. 页面在网络失败后会出现「改用 GitHub 提交」按钮，点击后打开预填好的 Issue 表单。
2. 「复制反馈内容」按钮始终可用，可取走整理好的文本自行提交。
3. 表单草稿保存在浏览器本地，关闭页面后重新进入仍可恢复；成功提交后自动清除。

## 回声洞投稿有限制吗

有。单条文本不超过 200 字符。投稿写入草稿后进入审核队列，审核通过才会出现在页面上。

## 上传文件有多大限制

单文件上限 2.5 GB（天花板是 OSS 单次 PUT 的 5 GB，再大必须分片）。比它大的文件请改填官网或 GitHub Releases 直链。

## 下载提示额度用尽

本站 OSS 对象采用票据闸门机制：每台设备每天默认 80 次下载额度，凭 15 分钟短时票据取流。额度用尽后请次日再试，或改用该软件的官方直链。
